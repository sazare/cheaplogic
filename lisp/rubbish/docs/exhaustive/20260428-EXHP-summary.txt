3. EXHP

　任意のclase set Σが与えられたとき、Π(Σ) = {p : Σ⊢□}を考える。pは証明。
  Π(Σ)がどういうものなのかを知りたいし、それに対して手続き的な表現を与えたい。
　Σ自体clauseの集合という表現は、そのひとつの関係による表現なので、表現形式を変えるということかもしれない。

　どういう書き方をするのかという点も気になる。

　ただし、どのような方法を考えたとしても、Π(Σ)の構造を完全に判定することは無理だと思うので、
　どこまで役にたつ情報が得られるのかを気にする必要がある。

　手続き的な表現に変換し、その手続き的な表現をなんらかのインタープリターで実行できるようにするとかいう方法で、　　問題点を分離することができないかなとは思う。
　　難しいところを計算という野生の概念に委ねるというかんじ。


　Exhaustive Proof(EXHP)と呼ぶのは、clause set Σに対して、そのすべての要素を使った証明のことをいう。
  {+P, -P}にはEXHPが存在するが、{+P, -P, +Q}にはEXHPは存在しない。

　□ の証明が存在するなら、EXHPなΣの部分集合があるということなので、EXHPな部分集合Σiを調べればΠ(Σ)がわかるのではないか。という意図。
　　
　任意のclase set Σが与えられたとき、Σの要素clausesは有限個なので、その部分集合Σ1, Σ2, ..., Σm ⊂ Σは有限個(2^N)しかない。

　だから、有望。

　問題点はふたつある。

　1) Factoring
　　同じ述語のリテラルが二つ存在するということはやっかいだ。

　2) Loop
　　p:Σ⊢□ があったとき、pの一部を反復することで、異なるpが作られうる。

　　その場合、同じclauaeが複数回使用されるので、区別すべきかもしれない。
　　DVCによって、同じ形のclauseでも変数の違うものがありうるから、複数回使われるその回数分だけclauseを複製しておき、EXHPでは繰り返しは認めないとするもの。
　　この場合は、部分集合が有限個ではなくなるので、前提が崩れる。崩れてもかまわなければこれはわかりやすい。

　　そうでなく、EXHPでは、同じclauseを繰り返し使ってもよいと考えることもできるだろう。
　　DVCによってresolventは異なる変数名になるので、操作的には可能。
　　よいのかどうかよくわからない。

　　Π(Σ)の構造を調べるにはどちらも何か力不足な気はするので、状況をみていく。
